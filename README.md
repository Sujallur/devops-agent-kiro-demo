# AWS DevOps Agent + Kiro: "A bad commit breaks checkout" (15-minute demo)

**Story:** a commit titled "Add coupon support" ships a bug. Orders without a coupon crash the `demo-checkout`
Lambda and a CloudWatch alarm fires. **AWS DevOps Agent** finds the root cause and the commit behind it.
**Kiro** (IDE/CLI) reads those findings, fixes the code, adds a test, and shows the diff. You push the fix and the alarm clears.

```
Push bad commit ──> Lambda errors ──> CloudWatch alarm
                                           │
        AWS DevOps Agent ◄─────────────────┘  (logs + metrics + GitHub code → root cause + mitigation)
              │
              │  MCP (read-only token)  or copy/paste of the findings
              ▼
        Kiro IDE / CLI  ──> fix + test + git diff ──> you push ──> alarm back to OK
```

Kiro autonomous agent (preview) is an optional variant: see [Optional: Kiro autonomous agent](#optional-kiro-autonomous-agent).

---

## 0. Before you start: decisions and risks

| Item | Guidance |
|---|---|
| AWS account | Use a **dedicated Isengard demo account** in **us-east-1**. It must not be a customer or production account. |
| AWS Support plan | DevOps Agent requires an eligible AWS Support plan on the account. **Check this first.** If the console says the service isn't available, resolve the plan before anything else. |
| GitHub repo | A **public** repo is fine. Never commit tokens or account IDs. `demo-private/` (the bug and the baseline) is git-ignored so the answer key isn't visible to the agent. |
| Public exposure | Nothing here is internet-reachable. The Lambda has no URL or API Gateway, and traffic is generated by direct `aws lambda invoke`. |
| Audience | Show the Agent Space and Kiro screens only. Never show the access token, account IDs in URLs, or Isengard pages. |

## 1. Permissions checklist

### AWS (Isengard demo account)
Sign in to the demo account with a role that can create resources. Use **Admin only on this demo account**, and use ReadOnly for anything else.

| Task | Needed |
|---|---|
| Deploy the stack (`scripts/deploy-infra.sh`) | CloudFormation, IAM (create role), Lambda, CloudWatch alarms |
| Ship code (`scripts/deploy-code.sh`) | `lambda:UpdateFunctionCode`, `lambda:GetFunction` |
| Send traffic (`scripts/load.sh`) | `lambda:InvokeFunction` |
| Create the Agent Space and associate the account | AWS DevOps Agent admin console access, plus IAM permission to create the Agent Space roles. The console can create the default roles for you. |
| Create the Kiro access token | `aidevops:CreateAccessToken` (plus `RevokeAccessToken` and `RotateAccessToken` for cleanup and rotation) and permission to update the Agent Space configuration |
| Optional SigV4 instead of a token | IAM permission to invoke DevOps Agent actions, plus `uvx` installed |

### GitHub
| Task | Needed |
|---|---|
| Register GitHub in DevOps Agent | Admin on your user account or organization, and permission to install GitHub Apps. If the target is an organization you must be an **organization owner**. |
| App permissions | Choose **Read-only** for this demo (the agent only needs to read code and PRs). Read and write lets it comment on PRs and propose fixes, which is not needed. |
| Push demo commits | Write access to your demo repo, via a working `git push` (SSH key or credential helper) |
| Kiro autonomous agent (optional) | The **Kiro Agent** GitHub App installed on the repo, and Kiro Pro, Pro+ or Power |

### Kiro
| Task | Needed |
|---|---|
| Kiro IDE or CLI | You are signed in. |
| DevOps Agent MCP | A DevOps Agent access token (**read** scope), and the env vars `DEVOPS_AGENT_TOKEN` and `DEVOPS_AGENT_REGION` set where Kiro starts |
| Autonomous agent (optional) | Kiro Pro, Pro+ or Power, and rollout of the preview to your account |

## 2. One-time setup

### Step 1: Open your terminal and check the tools
Open **Terminal** (macOS) and run each line. Each should print a version, not "command not found".
```bash
aws --version        # AWS CLI v2
git --version
python3 --version
zip -v | head -1
```
Keep this terminal open. All commands below run from the demo folder, wherever you keep it:
```bash
cd <path-to>/devops-agent-kiro-demo     # for example: cd ~/devops-agent-kiro-demo
pwd                                     # confirm; you should see app/, infra/, scripts/ with `ls`
```

**Want the project in a different folder?** The scripts find their own location, so nothing inside the project needs editing. Move or copy the **whole folder**, including the hidden files and `demo-private/`:
```bash
mv /Users/sujallur/devops-agent-kiro-demo ~/projects/devops-agent-kiro-demo     # move
# or: cp -R /Users/sujallur/devops-agent-kiro-demo ~/projects/devops-agent-kiro-demo   # copy
cd ~/projects/devops-agent-kiro-demo
ls -A        # expect: .gitignore .kiro app demo-private infra scripts tests README.md
```
Then reopen that folder in Kiro (File, Open Folder, or run `kiro-cli chat` from it) so `.kiro/settings/mcp.json` and the steering file are picked up.
Do this **before** `git init` in Step 2. If the folder is already a git repo, moving it keeps the history and the remote.

Important: `demo-private/` is git-ignored, so it is **not** in GitHub. If you later `git clone` the repo to another machine or folder, copy `demo-private/` over by hand, otherwise `break.sh` and `reset.sh` will fail.

### Step 2: GitHub - create the repo and push the code
**2a. Sign in and create the repo (browser)**
1. Open https://github.com and sign in.
2. Click **+** (top right), then **New repository**.
3. Repository name: `devops-agent-kiro-demo`. Visibility: **Public**.
4. Leave "Add a README", ".gitignore" and "license" **unchecked** (the folder already has files).
5. Click **Create repository** and copy the repo URL shown (SSH `git@github.com:<you>/devops-agent-kiro-demo.git` or HTTPS).

**2b. Check that git can push (terminal)**
```bash
ssh -T git@github.com     # SSH: expect "Hi <you>! You've successfully authenticated"
# If you prefer HTTPS, install and sign in with the GitHub CLI instead:
# gh auth login
```

**2c. Push the code (terminal, from the demo folder)**
Files that will be pushed (for information only, **do not paste this into the terminal**):
- `.gitignore`, `README.md`
- `.kiro/settings/mcp.json`, `.kiro/steering/remediation.md`
- `app/checkout.py`, `tests/test_checkout.py`
- `infra/template.yaml`
- `scripts/`: env, deploy-infra, deploy-code, load, break and reset (`.sh`)

Copy and run **only** the commands in the grey code blocks below.
Check what git will include before committing: `git status --short` (no `demo-private/` line should appear).

```bash
git init -b main
git add .
git commit -m "Initial checkout service"
git remote add origin git@github.com:<you>/devops-agent-kiro-demo.git   # use your URL from 2a
git push -u origin main
```
**2d. Verify (browser):** refresh the repo page. You should see `app/`, `tests/`, `infra/`, `scripts/`, `.kiro/`, `README.md`.
`demo-private/` must **not** be there (it is git-ignored). If it is, stop, delete the repo, and fix `.gitignore`.

### Step 3: Open your AWS account (Isengard demo account, us-east-1)
**3a. Get to the account (browser)**
1. Sign in to Midway if prompted, then open https://isengard.amazon.com.
2. Find your **demo** account (the one you chose for this demo, not a customer or production account) and note its 12-digit account ID.
3. Click the account, then **Console**, and pick a role that can create resources (Admin on this demo account is fine).
4. In the AWS console, set the region (top right) to **US East (N. Virginia) us-east-1**.

**3b. Get CLI credentials into your terminal**
```bash
mwinit -f      # refresh your Midway login (a security key / PIN prompt appears)
ada credentials update --account <ACCOUNT_ID> --provider isengard --role <ROLE_NAME> --profile demo --once
export AWS_PROFILE=demo
export AWS_REGION=us-east-1
```
Replace `<ACCOUNT_ID>` and `<ROLE_NAME>` with the values you used in 3a. If `ada` is unavailable, use the Isengard UI's "Get credentials" option and paste the exports into this terminal.
Credentials expire after a short time. Rerun the `ada` line if you see `ExpiredToken`.

**3c. Verify you are in the demo account**
```bash
aws sts get-caller-identity
```
Check that `Account` is your demo account ID. Stop if it is not.

### Step 4: Deploy the app with the scripts
Run these from the demo folder, in the same terminal where `AWS_PROFILE=demo` is set.

| Order | Command | What it does | Expected output |
|---|---|---|---|
| 1 | `./scripts/deploy-infra.sh` | Creates the stack `devops-agent-kiro-demo`: Lambda, role, alarm | "Successfully created/updated stack" |
| 2 | `./scripts/deploy-code.sh` | Zips `app/checkout.py` and uploads it to the Lambda | "Deployed app/checkout.py to demo-checkout" |
| 3 | `./scripts/load.sh 3` | Sends 3 healthy test orders | `...` (no errors) |

If a script says "Permission denied", run `chmod +x scripts/*.sh` once.

**Verify (browser, AWS console, us-east-1):**
1. CloudFormation: stack `devops-agent-kiro-demo` shows `CREATE_COMPLETE`.
2. Lambda: function `demo-checkout` exists.
3. CloudWatch, Alarms: `demo-checkout-errors` shows **OK** (or "Insufficient data", which is also fine at this point).

### What each script does (for reference)
| Script | Use it when |
|---|---|
| `scripts/deploy-infra.sh` | Once, at setup |
| `scripts/deploy-code.sh` | After any code change you want live (also used in the demo to ship the fix) |
| `scripts/load.sh N` | To send N test orders |
| `scripts/break.sh` | **During the demo:** pushes the bad "Add coupon support" commit to GitHub, deploys it, and sends traffic |
| `scripts/reset.sh` | Between demos: restores the healthy code, pushes it, redeploys |

### Step 5: AWS DevOps Agent
Console: AWS DevOps Agent, region us-east-1.
1. **Create Agent Space:** name `checkout-demo`. Let the console create the default roles.
2. **Associate the AWS account:** the demo account. Scope to the tag `Project = DevOpsAgentKiroDemo` if the option is offered.
3. **Connect GitHub:**
   - Register GitHub (account level), choosing **App registration**, **User** or **Organization**, and **Read-only**.
   - Authorize and install the app in GitHub, **limited to the demo repo**.
   - In the Agent Space, connect the demo repo.
   - Docs: https://docs.aws.amazon.com/devopsagent/latest/userguide/connecting-to-cicd-pipelines-connecting-github.html
4. **Enable access tokens:** Agent Space, Configuration, Access tokens, **Enable**.
5. **Create the token:** open the Agent Space web app, then Settings, Access Tokens, **Create access token**.
   - Name `kiro-booth`, scope **read**, expiry 7 days, IP allowlist if you can.
   - Copy the value into your password manager. It is only shown once.

### Step 6: Kiro
1. Add to `~/.zshrc`, then **restart Kiro** (the IDE, or a new terminal for the CLI):
   ```bash
   export DEVOPS_AGENT_TOKEN="<paste token>"
   export DEVOPS_AGENT_REGION="us-east-1"
   ```
2. Open this folder in Kiro. `.kiro/settings/mcp.json` already points at
   `https://connect.aidevops.us-east-1.api.aws/mcp`. Optionally install the **aws-devops-agent** power from the Kiro Powers marketplace instead.
3. Check the connection: in Kiro run `/mcp` (CLI) or open the MCP panel (IDE). The DevOps Agent tools should be listed.
4. Smoke test: ask Kiro "Give me a one-paragraph status of the demo-checkout environment." (Allow about 30 seconds.)
5. Steering file `.kiro/steering/remediation.md` is already in place, so Kiro will keep the fix small and won't deploy anything.

### Step 7: Rehearse once end to end
Run the full flow (section 3) once and **keep the finished DevOps Agent investigation open in a browser tab** as the booth backup. Then run `./scripts/reset.sh`.

## 3. Run of show (target 12 to 15 minutes)

| Min | Tool | What you do | What you say |
|---|---|---|---|
| 0-1 | Slide or whiteboard | Show the flow diagram above | "A page on a service you don't own. How fast can you find the cause and ship a fix?" |
| 1-3 | GitHub, terminal, CloudWatch | Open the repo. Run `./scripts/break.sh`. Open the CloudWatch alarm. | "A team just shipped 'Add coupon support'." The alarm goes to ALARM after 1-2 min. |
| 3-8 | **AWS DevOps Agent** web app | Start an investigation: *"Investigate why the demo-checkout Lambda is erroring."* Narrate the trace. Show root cause, the commit, and the mitigation. Switch to the pre-run tab if it's slow (live runs take 5-8 min). | "It correlates metrics, logs and the recent commit for me." |
| 8-13 | **Kiro** (IDE or CLI) | Paste the prompt below. Show the MCP call, the edit, the test run, and `git diff`. | "Now the developer uses the findings right in the editor." |
| 13-14 | Terminal, CloudWatch | `git commit -am "Fix: handle orders without coupon" && git push`, then `./scripts/deploy-code.sh`, then `./scripts/load.sh 5`. Alarm back to OK. | "Human reviews, agent did the legwork." |
| 14-15 | Wrap | Cover the talking points below | |

**Kiro prompt:**
> Ask AWS DevOps Agent for the latest investigation of the demo-checkout Lambda. Summarize the root cause in two sentences, then fix it in app/checkout.py, add a test in tests/test_checkout.py that reproduces the bug, run the tests, and show me the git diff. Follow the steering rules.

**Expected result (confirm in rehearsal):** `KeyError: 'coupon'` when an order has no coupon. Fix: use `event.get("coupon")` and apply the discount only when a coupon is present. The new test covers both cases.

**If the MCP call fails or is slow:** copy the root cause text from the DevOps Agent web app and paste it into the Kiro chat. The rest of the flow is identical.

**Talking points for ES and UOps customers**
- Faster time to root cause: logs, metrics and code in one place, without paging three teams.
- Humans stay in control: the investigation is read-only, the token is `read` scope, and Kiro won't deploy.
- Auditable: token use is logged in CloudTrail with the token name and source IP.
- Fits what they already run: CloudWatch, GitHub and other observability and CI/CD tools.

## 4. Optional: Kiro autonomous agent

Use this only if the preview is enabled for your account (Pro, Pro+ or Power, rolled out in stages). Setup:
1. Sign in at `app.kiro.dev/agent`, then Settings, Connect, GitHub. Authorize the Kiro Agent app on the demo repo only.
2. After the DevOps Agent investigation, create a GitHub issue with the root cause and mitigation (no secrets), then add the label `kiro` or comment `/kiro`.
3. Show the task progress in `app.kiro.dev/agent`, then review the PR it opens. Use `/kiro fix` or `/kiro all` for review feedback.

The agent follows instructions found in repo content, so use it only on repos you trust. The issue handoff is manual.
It doesn't replace the IDE/CLI flow above, so rehearse both before choosing.

## 5. Reset and cleanup

- **Between runs (about 1 minute):** `./scripts/reset.sh` restores the baseline code, pushes it, redeploys, and warms up the Lambda.
- **Rehearsal leftovers:** if the PR or commit history gets noisy, create a fresh repo.
- **End of event:**
  ```bash
  aws cloudformation delete-stack --stack-name devops-agent-kiro-demo --region us-east-1
  ```
  Then revoke the access token (Agent Space web app, Settings, Access Tokens), remove `DEVOPS_AGENT_TOKEN` from `~/.zshrc`, delete the Agent Space if unneeded, and uninstall the GitHub App from the demo repo.

## 6. Troubleshooting

| Symptom | Fix |
|---|---|
| DevOps Agent not available in the console | Check the Support plan on the account (section 0). |
| Alarm doesn't fire | Run `./scripts/load.sh 20` again. The alarm needs 3 or more errors in a 60-second window. |
| Kiro doesn't list the DevOps Agent tools | Restart Kiro after setting the env vars. Check the token isn't expired or revoked and the region matches. A 401 means a bad token. |
| MCP timeouts | Keep the timeout at 120 seconds or more (already set in `mcp.json`). |
| Agent says it can't see the code | Check the repo is connected to the Agent Space and the GitHub App is installed on that repo. |
| Tool calls return empty data | Check the Agent Space account association and its roles. |
